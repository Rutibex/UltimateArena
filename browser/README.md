# Ultimate Arena — The Foundry

A ROM-free, browser-based arena-shooter prototype combining extracted Perfect Dark weapon definitions and an adapted firing-spread rule with textures generated by the actual OpenKTG C++ library from the supplied kkrieger archive.

**Scope:** this is a new JavaScript/WebGL runtime with a Node.js match host. It is **not** the Perfect Dark PC engine running without a ROM, and it is **not** a completed merger of the two original engines. The original Perfect Dark movement, AI, renderer and networking have not been ported into this runtime. This package tests an independent arena/gameplay direction and a small procedural-content bridge. See [docs/INTEGRATION.md](docs/INTEGRATION.md) for exactly what was reused.

## Play on Windows

1. Install **Node.js 22 or newer** from <https://nodejs.org/> if it is not installed.
2. Extract this entire folder.
3. Double-click **Start-Arena.cmd**. Keep the terminal open.
4. Open <http://localhost:8080/> if the browser does not open automatically.
5. Choose **ENTER THE ARENA** for solo play against five bots. Click the game if mouse capture is needed.

There is no `npm install`, no ROM, no asset download, and no native compilation required to play. Use a recent desktop browser with WebGL 2 and hardware acceleration enabled. Do not open index.html directly from disk.

Linux/macOS: run `./start.sh` or `node server.js`, then open the same address.

## Included slice

- One original 48 × 48 metre arena: central reactor, cover lanes, two elevated galleries, four staircases and two jump pads.
- Accelerated movement with friction, air steering, jumping, dodging and collision against the same solids used by rendering and bot navigation. Crouch lowers movement speed and reduces firing spread; it does not change the collision capsule or eye height in this prototype.
- Six weapons, alternate functions, ammunition and resupply points.
- Five robot bots, generated navigation routes, target selection, line-of-sight shooting, range-based weapon selection and strafing.
- Free-for-all deathmatch: 20 frags or eight minutes, two-second respawns and automatic next round.
- Health and armor pickups, armor absorption, kill feed, scoreboard, generated weapon models, robot models, synthesized weapon sounds and four OpenKTG-generated materials.
- An authoritative match host, up to eight human connections plus configured bots, 60 Hz simulation, 20 Hz snapshots and local movement prediction with acknowledged-input replay.

All six weapons are available from spawn for immediate testing. Pickups replenish ammunition; this slice does not yet use weapon ownership/progression.

## Host / join a match

Choose **JOIN HOST** to connect to the host that served the page. Solo practice uses a separate local simulation; it does not join the server's running match.

For two people on a LAN:

1. Host runs **Host-LAN.cmd**, or `node server.js --bind 0.0.0.0`.
2. Both players open `http://HOST-LAN-IP:8080/` in their browsers and choose **JOIN HOST**.
3. If Windows asks, allow the host through the firewall for your intended network.

The default server binds only to localhost. Change the port with `--port 8090`, or the server's bot count with `--bots 3`. Bot count is capped at ten. The solo button always creates five local bots.

Internet access needs a reachable host and TCP port 8080 routing, or deployment behind an HTTPS reverse proxy that supports WebSocket upgrades. NAT traversal, a public lobby, authentication, and production hosting are not implemented. Opening an HTTP LAN address can also be subject to a browser's pointer-lock policy; localhost is the most reliable first playtest location. This release's network validation used two clients over loopback TCP, not two remote computers or an internet connection.

## Tests

Run `npm test` or `node --test tests/*.test.js`. No package dependencies are installed.

## Asset regeneration

The generated PNGs are included. To rebuild them, install a C++ compiler (`g++`) and Python 3, then run:

```sh
python3 tools/extract_pd.py
python3 tools/build_assets.py
```

The generator compiles the unmodified OpenKTG library and executes four original material recipes. Intermediate compiler output is written to ignored `build/`. Procedural arena geometry, robots and weapon models are built directly from code at runtime. They do not reuse kkrieger's mesh generator.

## Source layout

- `shared/sim.js`: shared movement, collision, combat, arena, bot navigation and match rules.
- `shared/pd-data.js`: reproducibly extracted Perfect Dark firing data.
- `server.js`: HTTP and authoritative WebSocket match host; no dependencies.
- `public/`: WebGL renderer, controls, audio, interface and prediction.
- `tools/`: extraction, material recipes and generation.
- `vendor/`: selected source from the two supplied archives and original notices.
- `assets/`: four generated material PNGs.
- `tests/`: simulation, real TCP networking and client integration checks.
